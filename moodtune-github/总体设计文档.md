# 人脸情绪识别歌曲推荐系统 · 总体设计文档

> 版本：v1.1（评审定稿 · 已融入 2026-10-27 审核意见，作为开发基线）
> 技术约束：HTML5 + CSS3 + JavaScript + Vue 3 框架
> 核心命题：通过人脸获取情绪（本地算法）→ 情绪驱动的歌曲推荐（本地曲库 + 在线 API）
> 文档目的：明确系统边界、技术选型、**情绪识别算法**与**歌曲推荐算法**，供可行性审核

---

## 1. 项目概述

### 1.1 背景与目标

传统点歌系统依赖"人找歌"（搜索/翻列表），无法感知用户当下状态。本项目构建一个**"歌找人"**的智能点歌系统：用户通过上传照片、打开视频、实时摄像头、拍照四种方式露出人脸，系统在浏览器本地完成情绪识别，再由推荐算法匹配符合（或调节）当前情绪的歌曲并播放。

### 1.2 核心需求（来自课题要求，逐条对齐）

| # | 课题原文要求 | 本设计对应方案 |
|---|---|---|
| R1 | HTML5 / CSS3 / JavaScript + Vue3 框架 | Vue 3 (Composition API) + Vite 构建，全项目纯前端技术栈 |
| R2 | 输入图片 / 打开视频 / 实时摄像头 / 拍照 获取人脸 | 四种采集入口统一抽象为"人脸输入源"模块（见 §7.1） |
| R3 | 通过算法得到情绪，**算法使用本地的** | face-api.js（TensorFlow.js 封装），模型文件托管在 `public/models`，推理全程在浏览器端完成，不上传任何人脸数据 |
| R4 | 通过情绪推荐合适歌曲，**明确歌曲推荐算法** | 基于 Russell 环状情绪模型（Valence-Arousal）的歌曲匹配打分算法 + 情绪→在线检索词映射（见 §6.2） |
| R5 | 歌曲：下载一些到本地使用 + 好用的在线歌曲 API | 双轨曲库：本地精选曲库（带情绪标签 JSON）+ 在线 API（网易云/Meting 聚合，Deezer 备选）（见 §4.3） |
| R6 | 明确情绪识别算法 | face-api.js 三级流水线：人脸检测 → 68 关键点 → 表情分类网络，含视频时序融合策略（见 §6.1） |

### 1.3 交付形态

- 一个可在浏览器中运行的 Web 应用（`npm run dev` 即可演示）；
- 本地 Node BFF 代理服务（~30 行 Express 脚本：解决在线 API 跨域/防盗链，含限流与结果缓存）；
- 设计文档 + 算法说明（本文件及其实现）。

| 模块 | 功能点 | 优先级 |
|---|---|---|

| 音乐播放 | 播放/暂停/切歌/音量、播放列表、歌词显示（在线接口提供时） | P0 |

| 体验增强 | 识别动画/情绪仪表盘、历史记录与收藏（localStorage）、"换一批"、情绪不准时手动改选 | P1 |
| 个性化 | 基于反馈（收藏/跳过）微调情绪→风格权重 | P2（可选加分项） |

### 2.2 非功能需求

- **隐私**：人脸图像不出浏览器，全部本地推理（课题"算法使用本地"的强约束，也是卖点）；
- **性能**：模型首次加载 < 5MB（Tiny 系列），单帧识别 < 300ms（普通笔记本 CPU），实时模式 ≥ 5 FPS；
- **可用性**：在线 API 失效时系统必须完整可用（本地曲库兜底——演示场景的保险丝）；
- **兼容性**：Chrome/Edge 为主；摄像头需 `localhost` 或 HTTPS 环境。

## 4. 技术选型

### 4.1 前端框架

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | **Vue 3 + Vite** | 课题硬性要求；Composition API 适合封装"识别 composable" |
| 语言 | JavaScript（非 TS） | 课题指定 JS；降低复杂度 |
| 状态 | Pinia（轻量） | 管理识别结果、播放列表、曲库来源等跨组件状态 |
| UI | 手写 CSS3（Flex/Grid + 变量主题） | 符合"自然、简洁、有特色"的设计偏好，避免重型 UI 库 |
| 路由 | vue-router（3 页内） | 首页/识别页/播放页 |
| 播放 | 原生 `<audio>` 标签 | 播放/切歌/进度/音量最稳；频谱可视化留作可选扩展（届时引入 Web Audio API `AnalyserNode`） |
| BFF | Node + Express（~30 行） | 在线接口跨域+防盗链是"最容易翻车点"，前端直连 fetch 大概率失败：开发期 Vite proxy，部署期本服务（限流+缓存） |

### 4.2 情绪识别库（本地算法）

| 候选 | 评估 |
|---|---|
| **face-api.js（选定）** | TensorFlow.js 封装，浏览器本地推理，预训练表情模型开箱即用（7 类），17.9k stars，社区集成范例多。缺点：更新放缓，但功能稳定不影响使用 |
| MediaPipe Face | 检测/网格强，但**无现成表情分类**，需自训模型，超出课题范围 |
| 自训 CNN (FER2013) + tfjs | 工作量最大，精度不可控，不选；作为文档中的"进阶路线" |
| 云端 API（如 Face++） | **违反"算法使用本地"要求，排除** |

模型文件：`tinyFaceDetector`（快）+ `faceLandmark68TinyNet` + `faceExpressionNet`，合计约 2~3MB，放 `public/models/` 本地托管。

### 4.3 歌曲来源（双轨）

| 轨道 | 方案 | 说明 |
|---|---|---|
| **本地曲库（主）** | 精选 30~50 首 MP3 存 `public/music/` + `library.json` 元数据（歌名/歌手/风格/valence/arousal/歌词） | 完全离线可用、可解释性最强（每首歌有显式情绪向量标签）、演示零风险 |
| **在线 API（扩展）** | 首选 **Meting 系聚合接口**（`@meting/core` 或在线 meting-api 实例，聚合网易云/QQ/酷我，支持搜索、播放 URL、歌词、封面）；备选 **Deezer API**（免费、无鉴权、返回 30s 试听）；国内也可直接用网易云搜索接口（需自建代理解决 CORS） | 情绪→检索词映射后拉取候选（§6.2.4）；用 Vite devServer proxy 或 20 行 Node 代理即可 |
| 排除项 | Spotify（Audio Features 已对新应用关闭、完整播放需 Premium） | 调研结论 |

> 版权说明（评审确认）：本地曲库**不使用网易云/QQ 版权歌曲打包演示**，改用无版权音源（Free Music Archive、Pixabay Music）或 AI 生成音乐（Suno/Udio），规避演示时下架/封禁风险；在线源仅作检索试听用途。

### 5.2 数据流（一次完整识别-推荐）

1. 用户选择采集方式 → 统一产出 `ImageData / video 帧`；
2. 识别引擎：检测人脸 → 68 点定位 → 表情网络 → 7 维概率向量 `p = [neutral, happy, sad, angry, fearful, disgusted, surprised]`；
3. 实时模式做**滑动窗口时序融合**（§6.1.3），图片/拍照单帧直出；
4. 推荐引擎：`p → 目标情绪向量 (v*, a*) → 本地库打分排序 + 在线检索合并 → Top-8 列表（含匹配理由）`；
5. 用户点歌播放 → 反馈（收藏/跳过）写 localStorage → 供 P2 个性化微调。

## 6. 核心算法设计（课题两项"明确"要求）

### 6.1 情绪识别算法（本地）

#### 6.1.1 算法流水线（face-api.js 三级模型串联）

```
输入帧 (video/canvas/img)
  ① TinyFaceDetector (SSD-MobileNet 系)  → 人脸框 + 得分(阈值0.5)
  ② faceLandmark68TinyNet                → 68 点特征对齐（仿射校正）
  ③ faceExpressionNet (MobileNet 骨干 CNN) → 7 类 softmax 概率
输出：p ∈ R^7，主情绪 e* = argmax(p)，置信度 c = max(p)
```

调用形态（实际实现即三行核心 API）：

```js
const result = await faceapi
  .detectSingleFace(input, new faceapi.TinyFaceDetectorOptions())
  .withFaceLandmarks()
  .withFaceExpressions();   // result.expressions => {neutral:0.1, happy:0.78, ...}
```

7 类情绪：`neutral / happy / sad / angry / fearful / disgusted / surprised`（FER2013 标准分类体系）。

#### 6.1.1a 模型加载与预热（评审补充）

- 首页 `onMounted` 即静默 `Promise.all` 并行加载三个模型，避免用户开始采集才加载造成卡顿；加载进度以动画反馈；
- 权重文件为 Vite 静态资源（带文件名 hash），浏览器 HTTP 缓存天然持久化，二次访问秒开；
- 加载完成后执行一次**预热推理**（对空白 canvas 推理一遍），触发 WebGL 后端初始化，消除首帧延迟毛刺。

#### 6.1.2 判定与容错规则

- `c ≥ 0.55` → 采纳主情绪；`0.4 ≤ c < 0.55` → 提示"不太确定"并给出 Top2 供用户改选；
- **冷启动兜底（评审补充）**：`c < 0.4` 或无人脸 → 提示重新采集，同时**仍按 Neutral 策略给出"日常歌单"推荐**——保证系统任何情况下都有结果输出，不出现空屏报错；
- 侧脸/遮挡鲁棒性：连续采集场景用 §6.1.3 平滑弥补；单图场景提示"请正面光线充足"。

#### 6.1.2a 多人脸处理策略（评审补充）

真实照片/摄像头画面可能同时检出多张脸：

1. 默认选取**画面中心区域且面积最大**的人脸作为主识别对象（`detectAllFaces` 后按 `0.6·面积归一 + 0.4·中心度` 排序取首位）；
2. UI 在预览画面上为每张检出人脸绘制选择框，用户可**手动点选**指定识别对象；
3. 未选中的人脸框置灰，仅作提示不参与识别。

#### 6.1.3 视频/实时模式的时序融合算法

单帧表情分类噪声大，采用 **EMA（指数移动平均）+ 滑动窗口投票**：

```
P_t = α·p_t + (1-α)·P_{t-1}        // α=0.3，对数帧概率向量平滑
每 500ms 采样一帧（setInterval + requestAnimationFrame 节流，保证预览 ≥5FPS 流畅度）
e* = argmax(P_t)，要求窗口内 Top1 一致率 ≥ 60% 才锁定输出
```

**突变检测旁路（评审补充）**：EMA 对"突然大笑/变脸"反应迟钝，加入直通规则——

```
if (max(p_t) ≥ 0.85) → 打断 EMA，直接采用当前帧结果并重置窗口
```

**资源释放（评审补充）**：组件 `onBeforeUnmount` 必须 `getTracks().forEach(t => t.stop())` 关闭摄像头流并清除定时器，否则摄像头指示灯常亮、CPU 空转。

拍照模式：抓拍当前帧，等价单帧直出。

### 6.2 歌曲推荐算法

#### 6.2.1 理论基础：Russell 环状情绪模型（Valence–Arousal）

将情绪投影到二维连续空间：**效价 V（愉悦度，-1~1）× 唤醒度 A（激活度，-1~1）**。这是情感计算与情绪音乐推荐文献（AAAI'23、Earlham Capstone、MDPI'25）的主流框架，可解释性强，适合"明确算法"的评审要求。

#### 6.2.2 情绪 → 目标 V-A 坐标映射表（算法核心 1）

| 识别情绪 | 目标 V* | 目标 A* | 期望音乐风格画像 |
|---|---|---|---|
| happy | +0.8 | +0.5 | 欢快流行/舞曲/放克，BPM 110-140 |
| sad | -0.6 | -0.4 | 抒情/钢琴曲/慢歌（共情）→ 见 6.2.5 调节策略 |
| angry | -0.5 | +0.7 | 摇滚/说唱（宣泄）或 轻音乐（平复），二选一 |
| fearful | -0.5 | +0.5 | 治愈系/自然白噪音/温暖民谣（安抚降唤醒） |
| surprised | +0.3 | +0.8 | 电子/节奏感强的流行（延续兴奋） |
| disgusted | -0.4 | 0.0 | 幽默轻松/民谣（转移注意力） |
| neutral | +0.2 | 0.0 | 流行/轻爵士（日常歌单） |

> 概率向量非 one-hot 时，目标坐标按概率加权：`(V*, A*) = Σ p_i · (V_i, A_i)`——即"78% 开心 + 15% 惊讶"会生成插值目标点，天然支持混合情绪。

#### 6.2.3 本地曲库匹配打分（算法核心 2）

每首本地歌在 `library.json` 中预标注音频特征（人工标一次即可，来源可参考公开曲库的 valence/energy 统计）：

```
song = { id, title, artist, file, v_s ∈[-1,1], a_s ∈[-1,1], bpm, genre, lang, pop ∈[0,1] }
```

> **BPM 字段（评审补充）**：唤醒度与 BPM 高度相关。用户拉"想嗨一点"时，除调整 A* 外可直接过滤 `bpm > 120` 的曲目，效果更直接、解释更直观。

相似度与总分：

```
d(s) = sqrt( (v_s - V*)² + (a_s - A*)² )        // V-A 空间欧氏距离
sim(s) = 1 - d(s)/d_max                          // d_max = 2√2，归一化相似度

Score(s) = 0.55·sim(s) + 0.25·GenreBoost(s, e*) + 0.10·pop(s) + 0.10·Novelty(s)
```

- `GenreBoost`：风格画像命中表（如 happy→pop/dance +1，否则 0）；
- `Novelty`：近期未播放加分，避免"总推同一首"；
- 输出 Top-8，并附**可解释标签**："因为检测到您 78% 开心 → 推荐高能量欢快曲目"。

**多样性打散（评审补充）**：纯按 Score 排序易连续推出同一歌手/风格。排序后执行打散约束：**Top-8 中同一歌手最多 3 首、同一风格最多 4 首**，超限候选顺延至后位，与后位合格候选交换。

#### 6.2.4 在线 API 推荐链路（算法核心 3）

在线源无法直接拿到 V-A 特征，采用**情绪→检索词映射**（与 6.2.2 表同源）：

```
e* → keywords（如 happy→"欢快 流行"/"upbeat pop"；sad→"治愈 抒情"）
   → 调用在线搜索/歌单接口（Meting 聚合：search + url + lyric + cover）
   → 取播放量/热度排序前 N 首，与本地结果按 1:1 混排
   → 在线失败/无结果 → 静默降级为纯本地推荐
```

#### 6.2.5 共情 vs 调节双策略（评审亮点）

文献中两种立场：**mood-congruent**（推同情绪歌，共情陪伴）与 **mood-regulation**（推反向情绪歌，改善心情）。本系统默认策略：

```
正向情绪(happy/surprised/neutral) → 共情策略（延续情绪）
负向情绪(sad/angry/fearful/disgusted) → 调节策略：目标 V* 上调 +0.3（向积极牵引）
```

**UI 交互（评审确认，答辩加分项）**：

- 播放页提供明显的**"陪我难过 ↔ 让我开心"拨动开关**（共情 ↔ 调节），切换即重排推荐列表；
- "想嗨一点 / 想安静一点"滑杆直接改 A*（联动 `bpm` 过滤）→ 即时重排。

#### 6.2.6 个性化（评审确认：纳入本期，做减法实现）

不做机器学习更新，仅在 Pinia 维护 `userPreference = { genreWeights: {}, favIds: [], skipIds: [] }`：

- 收藏某歌 → 其 `genre` 权重 **+0.1**；跳过 → -0.05；
- 打分时叠加：`Score += genreWeights[s.genre] ?? 0`；
- localStorage 持久化，重启不丢。成本极低，但"越用越懂你"的效果立竿见影。

## 7. 功能模块详细设计

### 7.1 人脸采集层（四种输入源统一抽象）

| 方式 | 实现技术 | 输出 |
|---|---|---|
| 上传图片 | `<input type="file" accept="image/*">` + FileReader → `<img>` | 单帧 |
| 打开视频 | `<video src=URL.createObjectURL(file)>` 循环播放 | 帧序列（走 6.1.3） |
| 实时摄像头 | `navigator.mediaDevices.getUserMedia({video:true})` | 帧序列（走 6.1.3） |
| 拍照 | 摄像头预览中 `canvas.drawImage(video)` 抓拍 | 单帧 |

统一接口：`useFaceInput()` composable，输出 `{ source, start(), stop(), capture() }`，识别引擎不关心来源。

### 7.2 页面结构（3 页）

1. **首页**：品牌区 + 四种采集入口卡片（大图标、自然风格）；
2. **识别页**：视频/图像预览 + 人脸框绘制（canvas overlay）+ 7 情绪概率条形仪表盘 + 主情绪标签；完成后自动跳转；
3. **播放页**：Top-8 推荐列表（封面/匹配理由/来源角标：本地|在线）+ 播放器（进度/音量/歌词滚动）+ "换一批"/"手动改情绪"/反馈按钮。

### 7.3 组件与目录结构

```
src/
├── views/        Home / Detect / Player
├── components/   FaceCanvas, EmotionGauge, SongCard, AudioPlayer, LyricPanel
├── composables/  useFaceInput, useEmotionDetect, useMusicApi
├── services/     recommender.js(§6.2算法), library.js, online.js
├── stores/       emotion.js, player.js (Pinia)
├── assets/       styles(tokens.css)
public/
├── models/       face-api 权重（tinyFaceDetector/landmark/expression）

server/
```

### 7.4 数据设计

`library.json` 示例（每首歌的显式情绪向量即推荐算法的"物料"）：

```json
{
  "id": "L001", "title": "示例-晴天", "artist": "周杰伦",
  "file": "/music/L001.mp3", "cover": "/covers/L001.jpg",
  "v": 0.35, "a": -0.2, "bpm": 118, "genre": "pop", "lang": "zh", "pop": 0.9,
  "lyric": "/lyrics/L001.lrc"
}
```

历史记录/收藏/权重：localStorage `mrs.history[]`、`mrs.fav[]`、`mrs.genreWeights{}`。

### 7.5 异常处理机制（评审补充）

| 场景 | 处理 |
|---|---|
| 摄像头权限被拒 | 友好提示"请在浏览器地址栏左侧允许摄像头权限，或改用上传照片方式"，并高亮"上传图片"入口作为退路 |
| 音频加载失败（MP3 损坏/在线 URL 超时） | `audio.onerror` → 自动跳过该曲播放下一首，Toast 提示"网络波动，已跳过"；连续失败 3 次切回纯本地模式 |
| 在线 API 超时/5xx | 3s 超时静默降级为本地推荐，列表不出现空位 |
| 模型文件加载失败 | 自动重试 1 次，仍失败则展示离线引导文案（检查网络/刷新） |
| WebGL 不可用 | face-api 自动回退 CPU 后端，提示"识别速度可能变慢" |

### 7.6 UI/UX 细节设计（评审补充）

- **情绪仪表盘**：7 类概率用不同颜色的水平条形图（CSS3 transition 动画），主情绪高亮放大 + emoji 标识，其余半透明弱化；
- **识别加载态**：预览画面上叠加**雷达扫描动画**（conic-gradient 旋转），扫描线经过人脸框时点亮；
- **播放加载态**：切歌/缓冲时封面以**唱片旋转动画**呈现（`animation: spin 4s linear infinite`），暂停即停转；
- 整体视觉遵循"自然、简洁、有特色"：柔和渐变背景、圆角卡片、CSS 变量主题色随主情绪微调色温（happy→暖黄 / sad→雾蓝 / angry→暗红）。

## 8. 关键技术风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| K1 | 在线音乐 API 跨域+防盗链（原版 NeteaseCloudMusicApi 已停维护；公共 Meting 实例常不稳定；前端直连 fetch 大概率失败） | 在线推荐失效 | **本地曲库为主、在线为增强**；开发期 Vite proxy、部署期自建 ~30 行 Node BFF（@meting/core，含限流+缓存）；超时 3s 静默降级 |
| K2 | 单帧表情误判（侧脸/光线/遮挡） | 推荐跑偏 | 时序融合 + 置信度阈值 + **用户手动改选情绪**兜底 |
| K3 | 摄像头需安全上下文 | 演示打不开摄像头 | localhost 即可；文档注明手机演示需 HTTPS |
| K4 | 歌曲无现成 V-A 特征（Spotify 已关闭该接口） | 打分算法缺输入 | 本地库人工预标注 30~50 首（一次性工作）；在线源走检索词映射，绕开特征依赖 |
| K5 | face-api.js 模型首次加载 ~2-3MB | 白屏等待 | 进入首页即预加载 + 加载进度动画 |
| K6 | 音频版权 | 演示合规 | 本地曲库用可公开获取音源；在线仅 30s 试听（Deezer）/教学演示口径 |

## 10. 决策点评审结论（已确认 · v1.1 定稿依据）

| # | 决策点 | 评审结论 |
|---|---|---|
| D1 | 在线 API 主选 | ✅ **Meting 聚合 + 本地中文曲库**。公共 Meting 实例不稳定 → **自建 `@meting/core` Node 服务**（并入 BFF，见 §9-S5） |
| D2 | 本地曲库 | ✅ 30~50 首。**不使用网易云/QQ 版权歌曲打包演示**，采用无版权音源（Free Music Archive / Pixabay Music）或 AI 生成音乐（Suno/Udio）；由我按 7 类情绪画像预选并标注 v/a/bpm |
| D3 | 负向情绪策略 | ✅ 默认**调节策略**；UI 提供明显的**"陪我难过 ↔ 让我开心"拨动开关**（共情/调节切换，答辩加分项） |
| D4 | 后端 | ✅ **需要**。~30 行 Express 脚本作为 BFF：代理在线 API（解 CORS/防盗链）+ 接口限流 + 结果缓存 |
| D5 | P2 个性化 | ✅ **纳入本期，做减法**：Pinia 维护 `userPreference`，喜欢风格 +0.1 权重（见 §6.2.6），不做机器学习 |
